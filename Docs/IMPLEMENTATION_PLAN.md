# LiveFoot MVP 实施计划

更新日期：2026-10-13。当前：P0～P5 已实现并验证，包含 Editor 构建、五项自动化、无窗口 Game 和开发者 PIE 画面验收。本计划覆盖的 MVP 已完成。

依赖顺序：P0 → P1 → P2 → P3 → P4 → P5。Agent 每组改动后检查差异、执行相应 Editor 编译并记录结果；开发者负责必要的环境操作和最终画面确认。无真实结果时停留在“待验证”，不要勾选通过。

## P0：建立可信基线

**输入**：AGENTS.md、四份 Docs 文档、现有源码/资产、已确认 UE 5.6.0 安装。

**工作**：

1. 先执行 [构建模板](BUILD_AND_TEST.md#2-构建流程模板)，保存当前 `LiveFootEditor Win64 Development` 完整输出及退出码。
2. 只读确认运行时 GameMode/Pawn 类、蓝图父类重定向、Mesh/AnimClass/AnimationMode、脚骨索引和地图覆盖，填写技术设计的待验证项。
3. 核对关键引擎头文件和姿态更新顺序，记录本次实际工具链。区分历史日志、当前构建与当前运行结果。
4. 若有基线阻塞，在正式开发已授权范围内定位最小修复；已有 Combat 字段初始化错误不能删除玩法/模块来规避。环境/引擎故障先记录分析，不擅改引擎目录。

**产出**：可信基线记录、已确认资产链、真实 API 清单、已知问题处理范围。

**通过条件**：构建可复现；默认角色能够进入 Game；实际蓝图父类、GameMode、Mesh、AnimClass、脚骨已由自动化确认。PIE 画面仍需开发者确认。

## P1：组件与双脚采样

**输入**：P0 通过记录、TECHNICAL_DESIGN §3/4。

**工作**：新增 Diagnostics 类型与组件，在 ALiveFootCharacter 创建原生默认子对象；获取 Mesh、校验双脚索引与连续采样有效性；安排 Tick 依赖；异常原因限频日志。只最小修改角色接入，不动原模板输入/移动。

**产出**：双脚世界变换/脚底采样点、有效性与重置逻辑，基本点位调试。

**通过条件**：完整 Editor 编译；真实 Blueprint CDO/默认 Game 已确认 BP_ThirdPersonCharacter 自动继承组件；脚骨、左右映射和连续最终姿态采样已由自动化确认；缺一骨骼只影响对应脚；无蓝图节点。PIE 画面对齐已由开发者确认。

## P2：地面与接触相位

**输入**：P1、TECHNICAL_DESIGN §5。

**工作**：每脚一次射线、Owner 忽略、命中/法线/间距计算、脚底偏移校准；实现 Unknown/Contact/Swing、迟滞与时间确认；移动平台/不支持坡度显式标记。

**产出**：接触状态与完整射线结果、已记录的 Quinn 参数初值。

**通过条件**：Editor 编译；无窗口真实默认地图确认地面命中、待机 Contact；数值测试覆盖无地面、垂直速度、穿透和非静态地面；每帧不超过两次射线；跳跃、坡面和台阶 PIE 已由开发者确认。

## P3：速度与疑似滑步

**输入**：P2、TECHNICAL_DESIGN §6。

**工作**：骨世界速度、脚底切向速度、按实际 dt 平滑；接触滑步持续/清除计时；首帧、暂停/掉帧、瞬移、配置/Mesh/地面切换重置。为数学与状态边界增加小范围、有意义的自动化验证。

**产出**：速度/报警指标及受控样本测试记录。

**通过条件**：Editor 编译；静止、恒速、坡面投影、阈值短脉冲、离地、瞬移和 30/60/120 Hz 受控样本通过；真实冻结姿态滑步正例、移动地面 N/A 通过；实际渲染 FPS 与长时开销待手动测量。

## P4：调试输出、配置与生命周期

**输入**：P3、TECHNICAL_DESIGN §7。

**工作**：同一帧结果驱动脚点/射线/法线/速度箭头及 L/R 屏幕行；参数校验、检测/绘制/屏幕开关、开发期控制台入口；检测关闭、EndPlay、Mesh 切换恢复临时 Mesh 设置并清理本组件消息。补录真实命令、参数单位和默认值。

**产出**：可直接操作的完整 MVP 与使用说明。

**通过条件**：Editor 编译；固定屏幕 key、调试开关、骨名提示、缺失数据和 EndPlay/Mesh 设置恢复已由自动化/代码核对；PIE 颜色、文字和重复启动画面已由开发者确认；不新增 Slate/Control Rig 依赖或蓝图手动接线。

## P5：完整验证与交付

**输入**：P4、PRD 全部验收条目、BUILD_AND_TEST 自动化覆盖及剩余 PIE 矩阵。

**工作**：关闭编辑器进行完整 Development Editor / Win64 构建，执行全部自动化与 PIE 场景；按文档构造可复现滑步正例，与画面核对；回归移动/相机/跳跃，抽查组件开销。已有问题与新问题分别记录，必要修复后重跑受影响测试。

**产出**：最终差异清单、实际构建日志/退出码、测试记录/截图、默认参数/命令、已知限制、四份文档状态更新。

**通过条件**：源码、UHT、Editor 链接、五项自动化、无窗口 Game 和开发者 PIE 画面/交互矩阵均已通过。该结论基于实际构建/测试记录和开发者手动确认，不能以“已写代码”“旧 DLL 存在”或 Live Coding 替代画面验收。

## MVP 交付状态

正式开发和验证已完成。开发者已在 UE 5.6.0 默认地图中确认颜色、文字、开关、跳跃/落地、坡面/台阶、滑步正例、重复 PIE 和性能观察。后续工作属于扩展版本：平台速度补偿、更多接触点、批量分析/报告导出和 Control Rig 修正预览。
