# LiveFoot 产品需求（MVP）

更新日期：2026-10-13（Asia/Shanghai）。状态：LiveFoot MVP 已完成；UE 5.6.0 Development Editor / Win64 构建通过，五项自动化测试通过，无窗口 Game 和 PIE 画面/交互验收均已完成。

## 1. 定位与使用者

LiveFoot 是 UE 角色运行时的步态诊断工具。第一版观察最终可见脚部姿态，估计左右脚接触/摆动、显示脚部速度，并提示“疑似滑步”。它提供动画排查线索，不提供接触真值、医学诊断或自动修正。

目标用户：动画程序员、技术动画师、角色动画开发者。典型场景：在第三人称关卡中观察待机、行走、转向、跳跃和落地，检查动画与角色移动速度不匹配、脚底漂移及阈值设置问题。

开发分工：Agent 编写 C++ 和维护文档；开发者完成必要的工具链/编辑器操作、编译复核与画面验收。不要求开发者手动连接 Blueprint 节点。

## 2. 当前项目基线

- 已确认引擎：UE **5.6.0**，路径 `E:/UE/UnrealEngine-5.6.0-release`。注册表关联、`Engine/Build/Build.version`、项目构建收据与既有编辑器日志相互印证。
- 当前主模块为 `LiveFoot`；第三人称 C++ 角色为 `ALiveFootCharacter`。默认地图为 `/Game/ThirdPerson/Lvl_ThirdPerson`，全局 GameMode 配置指向 `BP_ThirdPersonGameMode`。
- 自动化加载真实蓝图并运行默认地图，已确认 `BP_ThirdPersonCharacter` → `ALiveFootCharacter`，网格 `SKM_Quinn_Simple`、动画 `ABP_Unarmed`、骨骼 `foot_l/foot_r` 和继承的 `UAnimFootDebugComponent`，详见 [技术设计](TECHNICAL_DESIGN.md)。
- 本次实际 Editor 构建退出码 0，UHT、源码编译与 DLL 链接通过。已有 Combat 三个字段初始化问题已最小修复，最新自动化运行未再报告对应错误；证据见 [构建与测试](BUILD_AND_TEST.md)。

## 3. MVP 范围

| 功能 | 必须提供的行为 |
| --- | --- |
| 双脚读取 | 按可配置骨骼名读取当前 Skeletal Mesh 的世界空间脚部变换，左右脚独立处理 |
| 地面检测 | 每帧每脚最多一次向下射线；显示射线、命中点和法线；忽略所属角色 |
| 状态估计 | 每脚输出 Unknown / Contact / Swing；高度/垂直速度迟滞与时间确认抑制抖动 |
| 速度 | 显示脚骨骼世界速度及接触采样点沿地面切平面的速度，单位 cm/s |
| 疑似滑步 | 在有效、稳定 Contact 且静态地面上，切向速度持续超过阈值时报警 |
| 实时显示 | C++ 调试绘制与屏幕左右脚数据，颜色和文字一致；可关闭显示 |
| 参数与异常 | 骨骼、脚底偏移、射线、接触/滑步阈值、平滑和调试开关可配置；无效数据明确显示原因 |

标准验收场景限于单个本地第三人称角色、PIE、静态碰撞地面、世界 Z 向上、正常动画播放。移动/旋转平台标记为不支持滑步判定；可显示接触和世界速度，但滑步显示 N/A，不作静态地面结论。异步姿态、暂停、瞬移和缺失骨骼必须安全处理。

## 4. 非目标

不包含独立 Slate 编辑器插件、批量动画资产扫描、报告导出、动画自动修改/烘焙、完整 Control Rig 自动修正、机器学习分类、外部依赖或不必要第三方库。现有动画中的 Foot IK 不在本次修改范围，检测结果可能已受其影响。

更多指标、批量分析、报告导出和 Control Rig 修正预览属于后续版本；本版只保留清晰的检测结果数据结构，不提前建设插件框架。

## 5. 用户流程

1. 按 [构建与测试](BUILD_AND_TEST.md) 构建 `LiveFootEditor Win64 Development`，打开默认第三人称地图。
2. C++ 默认子对象 `AnimFootDebug` 已自动接入现有角色；进入 PIE 即显示左右脚诊断，无需蓝图节点。
3. 依次待机、移动、转向、跳跃、落地，观察脚标记/地面射线及屏幕状态和速度。
4. 必要时通过组件属性调整骨骼名、脚底偏移与阈值；通过 `LiveFoot.Draw 0/1`、`LiveFoot.Enabled 0/1` 控制显示或检测。`LiveFoot.FreezePose 1` 是临时冻结姿态的测试开关，结束演示须执行 `LiveFoot.FreezePose 0`。
5. 记录可复现动作、参数、帧率和报警截图。疑似报警由开发者结合脚部画面复核。

## 6. 异常行为

- Mesh、动画实例或某脚骨骼在自动匹配后仍缺失：相应脚为 Unknown，显示原因，停止该脚速度/滑步计算；另一只有效脚继续运行。日志按原因变化输出，不逐帧刷屏。
- 无地面命中：有效采样的脚为 Swing；地面高度/切向滑步值为 N/A，不伪造地面。
- 首帧、无效时间步、暂停恢复、瞬移、Mesh/骨骼配置切换：清除历史，速度暂为 N/A，滑步为 N/A；重新获得连续有效样本后计算。
- 数据不有限、姿态未就绪或地面法线不符合坡度要求：Unknown 或明确的“不支持”原因，不输出误导性报警。
- 调试关闭：停止绘制并清理本组件屏幕行；检测关闭：同时清除历史和输出；不影响角色输入、动画或移动。
- 参数无效：运行时校验、限制范围或禁用相关指标并提示；不得崩溃。

## 7. 验收标准

代码、构建、数值、无窗口运行和 PIE 画面/交互验证均已完成。PIE 状态依据 2026-10-13 开发者手动确认，自动化覆盖和手动记录见 [构建与测试](BUILD_AND_TEST.md)。

1. `Development Editor | Win64` 构建退出码 0，完整日志可追溯；MVP 不新增编译错误或运行错误。已有错误必须单独记录处理状态。
2. 默认角色在 PIE 自动拥有诊断组件，实际左右脚骨骼与屏幕 L/R 对应，无需蓝图节点或新增资产。
3. 待机的有效支撑脚稳定显示 Contact；足够离地且无近地命中的脚显示 Swing；跳跃期间无接触滑步报警；落地后按配置确认时间恢复。
4. 速度用连续有效世界采样计算，不以角色根部速度冒充脚部速度；在 30/60/120 FPS 下按秒计算确认时间，受控速度误差目标不超过 5%。
5. 受控静态地面滑动样本超过阈值并持续确认时间后报警；低于阈值、短暂尖峰、Swing/Unknown 和移动平台不报警。须有合成数据验证以及可复现 PIE 正例记录。
6. 几何绘制与屏幕状态使用同一帧结果；显示脚标识、状态、命中、距离、速度、疑似滑步和无效原因；开启/关闭无残留长寿命调试对象。
7. 缺失骨骼、无地面、参数错误、暂停恢复、瞬移以及重复 PIE 不崩溃、无日志洪泛、无历史泄漏。正常运行每帧最多两次地面查询，不创建逐帧 UObject。
8. 交付包含最终 C++、参数说明、实际构建/测试记录和已知限制；未执行项目明确保留待验证，不能将待验证写成通过。
